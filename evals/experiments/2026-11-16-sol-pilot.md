# GPT-6.1 Sol direct-guide pilot

## Protocol

This is a small exploratory pilot of **direct access to the applicable guide**,
including its complete reference example. It does not measure search, automatic
skill selection, or performance on tasks outside the catalog.

- Agent: OpenCode **2.3.0**, a fresh `pbg-pilot` primary-agent session for each run.
- Model: **`openai/gpt-6.1-sol#medium`**, explicitly selected for every session.
- Tasks: `bound-concurrent-work`, `coalesce-cache-misses`, `verify-token-claims`.
- Design: two repetitions of each task in each condition, **12 runs / six pairs**.
- Conditions: public contract alone; the same contract plus the corresponding guide.
- Limits: **300 seconds and eight model steps per run**; no replacement runs after
  failure. No grader feedback or repair round is supplied to the agent.
- Order: task order shuffled with seed `20261116`; condition order reversed for
  the second repetition of each task. Runs execute sequentially.

Both groups receive byte-identical task contracts, agent configuration and user
prompt. Both read `CONTRACT.md` and `GUIDANCE.md`; the latter contains either the
full guide or a statement that no additional guidance is supplied. Contract
clarifications expose the tested signatures, exception conventions and resource
ownership requirements to both groups.

The model may read those two files and its own solution, and may edit only
`solution.py`. Shell, web, skills, subagents, other tools and external directories
are denied. These are permission-restricted authoring sessions, not containerized
agent processes. The usual global instructions are shared between conditions;
their hash is recorded. Model invocation uses the user's configured provider.

## Grading

Generated Python executes only in a separate Docker container:

- Frozen project snapshot and dependency versions from `uv.lock`.
- Python **3.12.16**, pytest **9.2.0**, pytest-asyncio **1.5.0**, PyJWT **2.15.1**.
- Read-only root filesystem, read-only candidate mount, no network.
- Unprivileged user, dropped capabilities, no-new-privileges.
- One CPU, 512 MiB memory, 64-process limit and a 64 MiB temporary filesystem.
- Existing public grader with a 30-second contract timeout, plus a 45-second
  outer container timeout.

The image is
`sha256:55abbe5e2b9b5b9a21645a4ce9d671d39aebc4c0150738c2a0fd147376a85ee5`.
The bounded-concurrency reference passed in this environment before the first
agent run. Calibration of all three selected tasks, including their valid
alternatives and registered defects, passed after that run and before the
remaining eleven runs. Graders and inputs stayed frozen throughout.
The contracts contain eight concurrency checks, four singleflight checks and ten
JWT checks. Agents cannot read or change these checks during authoring.

The primary outcome is passing the entire selected contract. Record individual
check failures, agent/tool/grader errors, elapsed wall time and reported token

Provider prices are unavailable. A reported cost of zero is **not evidence of
free usage**; monetary cost is unknown. Wall times include OpenCode startup and
tool overhead. Cache usage and uncontrolled service load limit latency comparisons.

## Evidence and interpretation

The [machine-readable results](2026-11-16-sol-pilot.json) contain per-run outcomes,
token counters, timings, session IDs and source hashes. The
[evidence archive](2026-11-16-sol-pilot.tar.gz) contains inputs, generated solutions,
sanitized transcripts, orchestration scripts and the frozen grading source.
Its SHA256 is
`11d0d8cb6a8b67872c27dce355baaa72b55fbf57c0d06534863a0a5b5e2450be`.
Full local logs remain under `/tmp/opencode/pbg-sol-pilot.DfkNva/`.
The source snapshot was frozen before model calls; the checkout had no Git commit.

The archive is an evidence bundle, not an automatic replay command. Its scripts
record this machine's paths and refuse to rerun started trials. A new experiment
requires a fresh workspace, newly authorized model calls and equivalent inputs.

Two repetitions and three selected tasks cannot establish general agent uplift.
The guided group is given a reference solution, so this measures oracle-guide
assistance on near-reference tasks, not transfer to unfamiliar application code.
The graders were internally reviewed and calibrated, not independently certified.
No claim of independent technical review or statistically reliable superiority
should be inferred from this pilot.

## Results

All twelve approved runs completed within budget. Every assistant message used the
selected Sol model and variant. There were no agent, tool or grader errors,
timeouts or replacement runs. Input and solution hashes were verified after
completion.

| Metric | Without guidance | With guidance |
| --- | ---: | ---: |
| Entire contract passed | 6/6 | 6/6 |
| Individual checks passed | 44/44 | 44/44 |
| Mean wall time | 30.115 s | 21.158 s |
| Median wall time | 27.812 s | 19.021 s |
| Reported input tokens, summed | 19,414 | 20,509 |
| Reported cache-read tokens, summed | 19,968 | 31,104 |
| Reported output tokens, summed | 3,233 | 2,919 |
| Reported reasoning tokens, summed | 1,635 | 638 |

Token fields are preserved as separate OpenCode counters; they are not added
together into an estimated bill. Reported cache-write tokens were zero in both
groups.

| Task | Without guidance: passes / mean time | With guidance: passes / mean time |
| --- | ---: | ---: |
| Bounded concurrency | 2/2 · 27.812 s | 2/2 · 19.021 s |
| Singleflight | 2/2 · 45.616 s | 2/2 · 29.539 s |
| JWT verification | 2/2 · 16.918 s | 2/2 · 14.914 s |

There were **zero guided-only or unguided-only successes** across the six pairs.
The correctness measure hit its ceiling in both groups. Guided runs were faster
in all six observed pairs, with an approximately 29.7% lower group mean wall time.
This is descriptive evidence from this pilot, not an established latency benefit:
the sample is small, guided inputs include the reference solution, and cache/service
effects were not isolated.

The next useful experiment should introduce application-level adaptation and
unfamiliar failure cases, use independently reviewed graders, and evaluate
the complete skill/search/retrieve workflow separately. Repeating these easy
near-reference tasks alone would not address the correctness ceiling.
